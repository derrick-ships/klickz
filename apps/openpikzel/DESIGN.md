# OpenPikzels design
Pinned visual target: the real app.pikzels.com editor captured in the browser. This is an Operate surface, not a landing page. Near-black background, slightly lifted composer, compact rounded controls, red active tab and generate action, restrained white typography. Sidebar 250px desktop, collapsible mobile; central composer max 820px; results and scored image below. A real upload or generation is the image content; no invented thumbnail results. Use Lucide icons, one system-compatible sans family, 14px body, 16px form text on mobile, accessible muted foreground, instant focus rings and reduced motion. Source palette and spacing live in src/app/tokens.css. Red is the user's explicit change from the reference's mint accent.

Bespoke brand imagery extends the same token palette into practical graphite/red studio still lifes. Generated Aperture and Signal scenes are branding surfaces only. The editor retains its compact layout; a small empty-state scene is removed when user work exists. There are no motion controls. Eligible visible scenes play a single ambient take (4.4 seconds plus a 240ms dissolve), then settle on the still. Reduced-motion/data-saving visitors never load video. Editing, hidden tabs and leaving the viewport stop motion. User-created thumbnails remain the only creation results. See ASSETS.md.

The four user-supplied Pikzels references (IMG_9011/9012/9013/9009) refine this same editor: a static, softly masked 24px dot field, dark relief on small controls, red light on active modes and the split Generate action, a borderless prompt field inside its composer, visible shared focus and quiet 120–180ms transitions. Red replaces the reference’s mint. No reference logos, reviews, usage figures or performance claims are reused. Mobile mode pills wrap in a balanced 3+2 layout with 44px touch targets. Modal entry is 180ms; reduced motion removes it. See UI_POLISH.md.

Mobile brand art uses a reserved 3:1 compact frame with identical still/video positioning, preserving the full red tile, front face and shadow across 320/375/390/414/430px. Responsive 672/960px WebP sources serve the real scene at appropriate resolution; the original 1344px source remains available. The empty-state poster is discoverable in server HTML instead of waiting for client library initialization. See PERFORMANCE.md for actual measured release gates and native-device limits.

Layout refinement keeps the Operate hierarchy: title/mode → direction → subject/style → image references → model/format → Generate. Subject/style and image references are real DOM groups; on phones they occupy separate rows. Settings use an explicit grid, stacking the model below 380px. Navigation becomes an overlay drawer at ≤1024px and remains a desktop column above it; closed navigation is inert. Drawer actions transfer focus to content, dismissal returns it to the opener. Shared dialogs have a programmatic heading. Spacing uses a 4px base (4/8/12/16/24/32/40/48). Provider onboarding puts key entry first, with compact provider status rows alongside on desktop and below on mobile. The art, red accent and roomy prompt remain unchanged. See LAYOUT.md.

Delight motion uses a single product signature: four red pixels register into a tile only after a successful draft save, never on history retrieval or failed work. Pointer/touch drawers use220ms entry/160ms exit, advanced controls160ms, with the shared ease-out curve. Keyboard navigation and focus remain immediate. Reduced motion preserves a100ms opacity acknowledgment without translation. No new loops, sounds, media or runtime dependencies are introduced. See DELIGHT.md.

Copy uses concrete actions and recovery: a draft is saved instructions, a prepared profile is an AI-written reference description, and a score is a visual rubric rather than CTR prediction. Credit use is explicit before optional image review, profile preparation and fixed-image generation. Previewing fixes and instant resize do not use AI generation credits. See CLARIFY.md for the terminology glossary.

The user selected the Review Studio Overdrive direction. For a saved image, the capped canvas and adjacent desktop inspector lead; mobile follows the same order in one column. Actual200px feed review and measured source dimensions replace device-frame decoration. Creation controls remain discoverable through modes/disclosure; drafts keep their own workflow. All backend and scoring semantics stay. Native modal Escape/focus and keyboard footprint defects are fixed. See OVERDRIVE.md and HALLMARK.md.
